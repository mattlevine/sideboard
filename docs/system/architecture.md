# Architecture

pnpm 9 workspace (`packages/*`, `apps/*`). Node ≥ 20. Public packages share one version (today `0.1.x`).

| Path | Package | Role |
|------|---------|------|
| `packages/core` | `@sideboard-ai/core` | Orchestration, worktrees, store, MCP, Slack, git |
| `packages/cli` | `@sideboard-ai/cli` | `sideboard` / `side` CLI (`sideboard mcp` / `sideboard-mcp`) |
| `apps/desktop` | `@sideboard-ai/desktop` | Electron board (depends on core via `workspace:*`). **Apple Silicon (arm64) only** — electron-builder dmg+zip; no Intel/x64. |
| `apps/slack-relay` | `@sideboard-ai/slack-relay` | Hosted Fly relay (Socket Mode + OAuth + static `site/`) |

CLI and MCP run **without** the desktop. Prefer fixing core + CLI first.

## Data flow (short)

- **Worktree threads** — one agent per git worktree (`thread/*`). Desktop / CLI / MCP create and drive them. After `git worktree add`, Orchestrator runs setup in the background in parallel with the first agent turn. Discovery order: `.sideboard` / `.conductor` `[scripts] setup`, then `.cursor/worktrees.json`, then conventional `script/setup` / `bin/setup` / `scripts/setup(.sh)`. `run_setup` re-runs the same chain. **Cowboy mode** is off until **Settings → Advanced → Cowboy mode**; then create may use the project folder on the default branch (no isolated worktree). Land is commit+push to that branch (no PR). Archive/purge never `git worktree remove` the project folder (same guard as an adopted primary checkout). Setup and auto-run do not start on cowboy create. Create-from-PR stores `prUrl` immediately. Create-from-branch still forks `thread/<team>` from the chosen ref; if that source branch already has a GitHub PR, Sideboard looks it up (`gh pr view` / `gh pr list --head owner:branch`) and persists `prUrl` so the right-sidebar pill matches create-from-PR. Later `gh pr …` tries the persisted URL, then the worktree branch (a PR opened from this chat), then the source branch. Several worktrees can archive at once; last-tab teardown is serialized per worktree (so sibling chat tabs still remove the checkout once) and `git worktree add`/`remove` share a per-repo lock (git’s `.git` lock). The sidebar shows progress on every in-flight row instead of a single `archivingId`. Worktree rows use glyphs (running spinner, error alert, git-branch when uncommitted) instead of color-only status dots.
- **Orchestration (Global)** — coordinator agent uses Sideboard MCP (`list_threads`, `create_thread`, `send_to_thread`, `ask_git`, `create_schedule`, …). It does not live inside a project worktree. Fleet playbook is one document written as both `AGENTS.md` and `CLAUDE.md` in the synthetic home (Claude vs Codex/Cursor filenames). First-turn prompt adds audience, goal, and workspace inventory only — not a third copy of the playbook. Each later turn prepends a short identity reminder (thread id + parentThreadId); the full tool playbook is not repeated. Injected Sideboard MCP is profile-split: worktree turns register only `present_*` / `ask_user` (cached tools prefix stays small and stable); orchestration gets list_*/Slack/Linear/fleet. Compacting the Sideboard transcript does not clear `sessionId` (CLI prompt cache) unless last-request occupancy is ≥750k of the 1M ring. Claude/OpenCode spawn opts into 1h prompt-cache TTL (`ENABLE_PROMPT_CACHING_1H` / `OPENCODE_ANTHROPIC_PROMPT_CACHING_1H`) unless the user forced 5m. Token totals are Claude-shaped (`inputTokens` uncached; cache extra). Codex and Brightsy report OpenAI-shaped usage (`cached_*` already inside input; Codex `reasoning_output_tokens` already inside output) — adapters subtract before the UI. Claude, Cursor SDK, and OpenCode already report additive cache. The message chip and context ring show last-request occupancy (`lastRequestTokens`) against a flat 1M window for every agent/model. Billed input+cache summed across every tool round stays in the tooltip. When the agent CLI reports USD (`total_cost_usd` on Claude, `cost` on OpenCode steps), it is stored on `TokenUsage.costUsd` and shown on the per-turn chip and thread Σ total.
- **Schedules** — local `schedules.json` jobs (Settings, `sideboard schedule`, orchestration MCP `create_schedule`) fire a prompt via `Orchestrator.send` on a named Global chat, or `startOrchestration` when no `threadId` is set. One-shot `at`, interval `every`, or 5-field `cron`. Only the desktop host arms timers (same drain ownership as MCP `send_to_thread`); MCP/CLI persist the store. Missed ticks catch up once on launch. Sleep skips until wake. Overnight runs opt in via Settings → Advanced → Caffeinate while schedules are enabled (same pattern as Slack Listen; default off so a 9am cron does not pin the Mac awake) or `set_caffeinate`. Recurring jobs without `threadId` open a new orchestration chat each run. Firing is `send` / `startOrchestration` only (not land/purge).
- **Slack** — hosted relay `wss://relay.sideboard.cloud/slack/desktop`. OAuth callback `https://relay.sideboard.cloud/slack/callback` (client secret stays on Fly). Desktop Listen registers this Mac; DMs/@mentions go to a per-user Global orchestrator chat (`sourceRef` `slack:<team>:<user>`). Closing or archiving that chat (or every Global tab) opens a new one on the next DM — Listen does not keep sending to History. A follow-up DM/@mention force-stops the in-flight coordinator turn and starts a new one (same `clearQueue` stop as MCP `send_to_thread`); send `stop` to cancel without a replacement prompt. After ~20s still running, Listen posts one `Thinking…` Slack message and `chat.update`s it from the live turn snapshot (tool names); the final answer replaces that same message. Coordinator replies stay Slack mrkdwn in the transcript (`<url|label>`, `•` lists); the board converts those links to CommonMark, turns `•` into markdown lists, keeps Slack single-newlines as hard breaks, and splits a same-line PR-link run (`apps/desktop/src/renderer/src/lib/slack-mrkdwn-to-markdown.ts`). Outbound `slack_post` (coworker pings) is different: human replies are appended as agent “information only” messages, then `Orchestrator.send` queues a follow-up on that posting chat without force-stopping the in-flight turn. Compute stays on the Mac (VPN); the relay routes Slack chat only. The machine must stay awake. Desktop JSON-pings the relay every 20s (pong timeout reconnects) so Fly/NAT idle cannot leave a zombie Listen socket while `/health` still shows `sessions: 0`. The same Fly app serves the marketing site at `https://www.sideboard.cloud/` (`site/`).
- **Present UI** — worktree `present_schema` / `present_artifact` / `present_files` open the structure column. Chat markdown is enough for read-only tables; do not also call `present_schema` just to re-display those rows (`formatArtifactDirective`). If the user asks for an editable table, `present_schema` is still allowed.

Desktop `predev` builds core. After core changes, rebuild core (or restart `pnpm dev`) before expecting the app to pick them up. The renderer may `import type` from `@sideboard-ai/core` but must not import values from the core barrel (that pulls Node `fs` into Vite). Value helpers go through `@sideboard/*` aliases in `apps/desktop/electron.vite.config.ts`.

**Nested Electron.** Sideboard.app leaks `ELECTRON_*` / `CHROME_*` (crashpad/GPU) into children. A nested Electron then dies at startup (`HasCustomHostObject` / `ElectronInitializeICUandStartNode`). Agent spawn and run scripts strip those keys. That is not enough when the immediate parent is also Electron — Cursor's local agent (Grok and other Cursor models) merges MCP env onto its own crashpad pipe, and the crash happens in `ElectronInitializeICUandStartNode` before JS can unset env. Cursor's SDK also spawns `.js` with `process.execPath` and strips `ELECTRON_RUN_AS_NODE` from child env — so an Electron-as-Node Cursor runner makes the local agent Sideboard.app (nested Chromium). The packaged app copies the Cursor runner, `@cursor/sdk`, `rg`, and the runner's production dependency tree (`execa`, `smol-toml`, SDK deps such as `zod` / `@bufbuild/protobuf`) into `Contents/Resources/cursor-runtime` (`extraResources`; `apps/desktop/scripts/stage-cursor-runtime.js`). Copying only the SDK package is not enough — ESM resolution cannot walk up to the repo `node_modules` from inside the app. Staging must also nest duplicate package names (pnpm's `get-stream@9` ESM for execa vs hoisted `get-stream@5` CJS for extract-zip) — flattening by name makes `import { getStreamAsArray } from 'get-stream'` throw. Shared copier: `apps/desktop/scripts/stage-node-deps.js`. Do not set `asarUnpack` — electron-builder `getRelativePath` requires every candidate under `apps/desktop`, and pnpm workspace links realpath into `packages/core`. Native `.node` modules still unpack via electron-builder's default smartUnpack. `resolveNodeLaunch` prefers a real `node` for those extraResources files. The packaged app ships official Node 22 LTS (`darwin-arm64`, not Homebrew) at `Contents/Resources/node/bin/node` (`apps/desktop/scripts/stage-bundled-node.js`; extraResources `node/`). Packaged Cursor and MCP use that binary so Homebrew Current + Cellar `libuv` cannot abort in `uv_run`. `isElectronLikeCommand` matches the GUI binary (`Contents/MacOS/Sideboard`) only — a `/Sideboard.app/` substring must not reject extraResources Node sitting next to it. `better-sqlite3` in `sideboard-mcp` is rebuilt against that same ABI. Unpackaged / CLI / `pnpm dev` still probe `node -v` across PATH plus Homebrew `node@20`/`@22`/`@24` kegs (and nvm/fnm/volta) and pick even LTS ≥20. Do not trust keg names — `opt/node@22` can alias the unversioned Current keg. Electron-as-Node remains the fallback only when no real Node exists (asar scripts). Native stacks are summarized (`error-detail.ts`).

**MCP is the CLI.** In-app agents and other Mac apps (Cursor IDE, Claude Code, Codex) spawn the same stdio server: a real `node` + filesystem `run-stdio.js` (or `sideboard mcp`). Packaged Sideboard.app uses extraResources official Node 22 (`Contents/Resources/node/bin/node`) plus `Contents/Resources/sideboard-mcp` (`apps/desktop/scripts/stage-sideboard-mcp.js`) with core's production dependency tree (`@modelcontextprotocol/sdk`, `execa`, `zod`, `@cursor/sdk`, …) and a Node-ABI `better-sqlite3` rebuilt for that bundled Node. Copying only sqlite is not enough — ESM resolution cannot walk up to the repo `node_modules` from inside the app. The isolated pack check must import `execa` (and fail on `SyntaxError` / named-export errors), not only `ERR_MODULE_NOT_FOUND`. MCP `command` is never Sideboard.app / Electron-as-Node when a real `node` exists. The board UI stays on in-process core/IPC. Packaged + other apps share `~/Library/Application Support/sideboard` (`SIDEBOARD_APP_DATA`). `pnpm dev` keeps `.sideboard/dev-app-data` so two orchestrators do not race one store. On packaged `app.whenReady()`, Sideboard writes `desktop-host.pid` and merges a `sideboard` entry into `~/.cursor/mcp.json` (and `~/.claude.json` if that file already exists) pointing at the same absolute node + extraResources MCP + store. Codex is documented the same way; we do not rewrite `~/.codex/config.toml`. MCP `send_to_thread` / `ask_git` persist the queue and do **not** drain while that pid is alive — the desktop watcher adopts so `turn_output` reaches the renderer. Without a live board, MCP/CLI drain themselves. `wait_for_turn` already polls the thread file, so it still unblocks across processes. Stop / Send now SIGTERM `agentPid` even when this process has no `activeTurns` handle. Send now always arms `drainQueue` (do not rely on a loop that may already have exited). `drainQueue` waits at most 2.5s for a live `agentPid`, then SIGKILLs — a wedged Cursor child must not pin the next Send now as a no-op (`draining` already set). The composer queue dock sits inside `.composer-shell` (same width as the input, including file/diff overlay) and lists follow-ups only — an idle send with an empty follow-up queue paints in the transcript, even while `thread.queue` still holds the prompt that will start next. Queue dock actions fire on `pointerdown` so composer collapse cannot steal the first click. Every MCP serializer still drops `ELECTRON_RUN_AS_NODE` from spawn env. Cursor SDK `mcpServers` include `type: "stdio"`. Brightsy is hosted chat and does not spawn local MCP. Helpers live in `packages/core/src/store/desktop-host.ts`, `packages/core/src/hook/nested-electron-env.ts`, `packages/core/src/agents/node-launch.ts`, `packages/core/src/agents/packaged-runtime.ts`, `packages/core/src/agents/injected-mcp.ts`, and `packages/core/src/agents/user-mcp-config.ts`.

**Cursor local store.** Sideboard uses `@cursor/sdk` `JsonlLocalAgentStore` under app-data `cursor-sdk-store/` (Electron's Node has no `node:sqlite`). The SDK only serializes JSONL writes **inside one process**; Sideboard spawns a runner per turn, so concurrent Cursor chats used to share `agents.ndjson` / `runs.ndjson` and last-write-wins dropped a run (`Run … not found for agent …`). Each thread now gets `cursor-sdk-store/threads/<threadId>/`. Agent rows point at a checkpoint `rootBlobId`; interrupted writes leave `.checkpoints.ndjson.*.tmp` and a missing blob. Resume then throws `Corrupt local agent checkpoint`, `Agent … not found`, or `Run … not found for agent`. The Cursor runner starts a fresh `Agent.create` (and the orchestrator retries once after clearing `sessionId`) instead of failing the turn.

**Other agents do not share that JSONL catalog.** Claude / Codex / OpenCode shell out to vendor CLIs and resume by session id (`claude --resume`, `codex exec resume`, `opencode run --session`). Sideboard does not keep a process-unsafe rewrite log for them. Claude MCP config is a per-turn `mkdtemp` file; OpenCode MCP is `OPENCODE_CONFIG_CONTENT` in the child env. OpenCode must never pass `--continue` (that flag is global under concurrency). Codex sessions live in `~/.codex` SQLite, which locks instead of silently dropping rows — nested Codex (orchestrator Codex spawning another Codex) can still deadlock on those locks, so detect/MCP must not spawn extra `codex` while an exec is live. Brightsy is hosted chat with no CLI session resume; it may rewrite `~/.brightsy/config.json` to select a team before spawn (token mix-up across teams, not a missing-run catalog).

**Cursor ripgrep.** The local agent indexes the worktree with `findFilesWithRipgrep`. The SDK walks from `argv[1]` for `node_modules/@cursor/sdk-<plat>-<arch>/bin/rg`. In the packaged app that path is inside `app.asar` (not executable), which surfaces as `findFilesWithRipgrep` + `[resource_exhausted]`. Spawn sets `CURSOR_RIPGREP_PATH` to `Contents/Resources/cursor-runtime/node_modules/@cursor/sdk-<plat>/bin/rg` (`packages/core/src/agents/cursor-ripgrep.ts`).

**Turn progress.** MCP clients (Cursor, Claude Code) often kill a tool call around 60s. `wait_for_turn` therefore returns within 45s with `stillRunning` plus a live snapshot (`threads/<id>.live.json` — last tool / thinking) instead of hanging until the transport dies. Coordinators loop `wait_for_turn`; they must not ping the child with “are you stuck?”. Status `queued` with no `lastActivityAt` means the child is waiting on the concurrency cap — it has not started, and coordinators must keep waiting (not `force_stop`). Slack/Brightsy `waitForTurn` still throws on true timeout. `listThreads` must ignore `*.live.json` — those sidecars are not thread records (no `id` / `worktreePath`); listing them made `get_thread` / turn-end branch sync throw mid-orchestration stream. The desktop `threads/` watcher must ignore those sidecars and atomic `*.tmp` writes too, and debounce `threads:changed`: notifying on every live flush made the renderer `getThreads` parse every transcript on the UI thread while several agents ran, so sidebar clicks felt frozen. The orchestrator must not `readThread()` on `tool_result` / `stderr` / `usage` (same main-thread parse); false “reconciled on startup” healing is throttled and limited to `tool_use` / `session_id` / `exit`. Helpers: `packages/core/src/store/turn-live.ts`, `packages/core/src/mcp/wait-for-turn.ts`.

**Turn failures.** Runner crashes used to live only on `lastError`. `wait_for_turn` returned `{ status, text }` with empty text, so the orchestrator could not switch agent or tell the user. Failures with no assistant output are appended as the agent message; `getTurnResult` includes `lastError` and fills `text` from it when the chat is empty. A dead Node/Cursor runner (native `uv_run` / truncated dump / empty exit / `Connection stalled` with no chat text) is respawned **once** with a fresh session — not credits, auth, or missing packages. Native abort stacks all end in `uv_run` / `SpinEventLoopInternal`; only Homebrew Cellar `libuv`/`node` gets the `brew install node@22` hint. Bundled official Node (`Contents/Resources/node`) is a generic retry. V8 `FATAL ERROR` / `OOMErrorHandler` / JavaScript heap is summarized as OOM. When the thread already has a `sessionId` (long-chat leak), it is retried **once** with a fresh session; first-turn indexing OOM (no session) is not, because the same folder would die again. Every agent spawn and injected Sideboard MCP sets `NODE_OPTIONS=--max-old-space-size=8192` unless a larger heap is already set (`applyAgentRunnerHeapEnv`). Pin those OOM lines in the stderr tail so hex frames cannot displace them. Checkpoint recovery logs (`unresumable — starting a new session`) must not hide a later `Cursor run failed:` line. Helpers: `packages/core/src/agents/error-detail.ts` (`turnFailChatText`, `shouldRetryFailedAgentTurn`), `packages/core/src/agents/node-launch.ts`.

**Stale `index.lock` after a crash.** A git child killed mid-write (an agent commit hit by the OOM/crash above) can leave `index.lock` under the worktree's gitdir or the main repo's `.git/worktrees/<name>/`; git then refuses every further command on that repo — Sideboard's own actions and the user's own terminal git alike — until the lock file is removed. Two layers recover it: `git()` (`packages/core/src/git/run.ts`) retries once on `Unable to create '…index.lock': File exists` after clearing any lock older than `STALE_INDEX_LOCK_MS` (20s — far longer than any single git command should hold it), so any Sideboard git call self-heals; the orchestrator's crash/OOM turn retry additionally clears the lock immediately (2s threshold) for the worktree it just confirmed died, instead of waiting on that generic timeout. Helper: `packages/core/src/git/stale-lock.ts` (`isIndexLockError`, `clearStaleIndexLocks`).

**Unattended git.** Agent and MCP children must not pop macOS Keychain or SSH passphrase dialogs during turns — orchestrator parents (desktop Global, MCP, Slack) cannot click them. Desktop `app.whenReady()` warms GitHub auth once (`gh auth token` or a stored PAT); Keychain is OK at that moment. The token is written to `~/.sideboard-git-auth/` (`git-credentials` + isolated `GH_CONFIG_DIR`, mode 0600). Agent env gets `GIT_CONFIG_*` (HTTPS `insteadOf`, `credential.helper=store --file=…`) and `GH_CONFIG_DIR` — **not** `GH_TOKEN` and not `http.extraHeader`. MCP start reuses those files and does not call `gh auth token` again. Account → GitHub mode `ssh` keeps SSH remotes but still batch-mode (fails instead of prompting); `gh` still uses the warmed config. Helpers: `packages/core/src/git/github-agent-auth.ts`, `git-auth-mode.ts`. All worktree agents share `spawnAgentTurn`; Sideboard MCP gets the same env in every serializer. Codex `workspace-write` needs `shell_environment_policy.inherit=all` + `ignore_default_excludes` so `GH_CONFIG_DIR` / `GIT_CONFIG_*` reach the sandbox, `sandbox_workspace_write.network_access=true`, and `sandbox_workspace_write.writable_roots` pointing at `--absolute-git-dir` plus `--git-common-dir` (Codex otherwise mounts `.git` read-only, so linked worktrees cannot create `index.lock` in the main repo’s `.git/worktrees/<name>/`). Setup/run scripts get the same git env. Brightsy is hosted chat and does not run local git.

**Cursor local hang.** Local SDK `send()` does not throw `agent_busy`. A killed runner leaves a persisted RUNNING run, and HTTP/2 stall retries can drop `toolCallCompleted` so the run never finishes — the worktree can be fully edited while `run.stream()` never closes, `wait_for_turn` blocks, and the chat UI shows only the user prompt. Each Cursor runner `send()` uses `local.force`, create/resume set `enableAgentRetries: false`, the stream iterator ends after `CURSOR_STREAM_IDLE_MS` (3 min) of silence, and SIGTERM/SIGINT cancel the live run (2s cap) before exit. Helpers live in `packages/core/src/agents/cursor-session.ts`. Do not default `useHttp1ForAgent` — that path has produced instant RUNNING→ERROR with no content. Merge/push still belong on `ask_git`, not a worktree prompt like `Merge PR.`

**Token-stream paint.** Claude `content_block_delta`, Cursor local `assistant`/`thinking`, and similar frames are often one word. `spawnAgentTurn` coalesces consecutive stdout/thinking (~32ms) before orchestrator IPC; the Cursor runner does the same before NDJSON. Consecutive frames only merge when they share a `parentId` (so a Task subagent’s thinking does not glue onto the parent). The orchestrator must not `readThread()` on stdout/thinking (sync JSON parse on the Electron main thread makes streaming look word-by-word). The board coalesces live paint to one React update per animation frame so several concurrent streams cannot starve clicks. Helper: `packages/core/src/agents/cursor-stream-coalesce.ts`. Claude `system/task_notification` patches the parent Agent card (`live_tool_uses` / duration) instead of concatenating thinking pulses. Chat paints a turn as chronological phases — collapsed “Thought for …”, visible mid-turn text, collapsed “Worked for …”, then the outcome. Thinking and tools with no agent text between them stay one collapsed “Worked for …” block so think→tool→think→tool does not become a stack of empty headers. Tools still summarize in the muted footer (`toolActivityLine` in `packages/core/src/agents/message-parts.ts`). While the turn is queued or running — including the wait before the first token — the brand mark and bouncing dots sit at the bottom of the live agent message (`msg-stream-activity`). A live log pane appears under a shell row only after the command has been running ~3s (`tool_result.partial` updates `result` while `status` stays `running`); short calls and finished tools stay a one-line row (click still opens the inspector). Codex forwards in-progress `command_execution.aggregated_output`; Claude, Cursor, OpenCode, and Brightsy fill the same pane when their CLI emits output. MCP `wait_for_turn` still uses `liveActivitySummary`.

**Cursor subagents.** The Cursor app UI streams nested Task / Agent work (inner thinking + tools) inside the parent tool. Sideboard maps that path: the runner passes `onDelta` on `send()`, and only `tool-call-delta` → nested task updates become `AgentEvent`s with `parentId` set to the parent Task call id. Top-level text/thinking/tools still come from `run.stream()` (do not also consume `text-delta` / `thinking-delta` on `onDelta` — that would duplicate). The board groups those parts under a subagent card. Nested stdout is not the parent answer. Nested deltas bump the stream idle clock so a quiet parent `run.stream()` does not look hung while the child is working.

**Other agents’ subagents.** Same `parentId` cards: Claude Code stream-json messages with `parent_tool_use_id` (Task / Agent; `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT=1` so thinking/text are forwarded). Headless `-p` auto-denies tools not in `--allowedTools`, so Sideboard also auto-approves `TaskOutput` / `TaskStop` (background Agent polls) and `EnterWorktree` / `Skill` (isolation worktrees + process guides). `system/task_started` and `system/task_notification` are progress — they carry `session_id` but must not become `--resume`; nested `system/init` is ignored for the same reason. `claude -p` abandons background agents after 10 minutes unless `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` is raised (Sideboard uses 2h). Codex `collab_tool_call` / `spawn_agent` (child bash/read stay sibling items in `codex exec --json` — only the spawn card plus any `agents_states` message nest); only `thread.started` is the parent session (not `*.started` child threads). OpenCode `task` keys by child `sessionId` when present and maps `subtask_event` / `subtask_delta` if the CLI ever emits them (`opencode run --format json` currently drops child-session events); child `step_start` must not steal `--session`. Brightsy has no nested coding subagent stream (`connectedAgentRequest` is a single tool card). Cursor Task/Agent uses one SDK `agentId` per runner, so nested system init is not a resume-steal path.

## Process skills

Recurring process guides are **Claude Code project skills** at `.claude/skills/<name>/SKILL.md` (committed). Sideboard discovers that folder (and `.cursor/skills`, legacy `.sideboard/skills`, …) for composer `/name` expand. Native Claude Code and `attach` load `.claude/skills` without Sideboard. New skills must not be written only under `.sideboard/skills`. The worktree playbook (`formatProcessGuideDirective`) and orchestrator playbook state this; the stock Review skill (`.claude/skills/review/SKILL.md`, seeded on worktree setup when missing) asks reviewers to propose a sentence for that skill when a missing rule will recur. Legacy `.sideboard/review.md` is copied into the skill on first setup.

This repo ships [`.claude/skills/graph-engineering/SKILL.md`](../../.claude/skills/graph-engineering/SKILL.md) (`/graph-engineering`) — the method for fan-out / batch work. `.cursor/skills/graph-engineering` is a symlink so Cursor sees the same file. `AGENTS.md` / `CLAUDE.md` point at it for Codex and OpenCode.
