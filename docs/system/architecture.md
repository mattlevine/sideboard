# Architecture

pnpm 9 workspace (`packages/*`, `apps/*`). Node ≥ 20. Public packages share one version (today `0.1.x`).

| Path | Package | Role |
|------|---------|------|
| `packages/core` | `@sideboard-ai/core` | Orchestration, worktrees, store, MCP, Slack, git |
| `packages/cli` | `@sideboard-ai/cli` | `sideboard` / `side` CLI (`sideboard mcp` / `sideboard-mcp`) |
| `apps/desktop` | `@sideboard-ai/desktop` | Electron board (depends on core via `workspace:*`). **Apple Silicon (arm64) only** — electron-builder dmg+zip; no Intel/x64. |
| `apps/slack-relay` | `@sideboard-ai/slack-relay` | Hosted Fly relay (Socket Mode + OAuth + static `site/`) |

CLI and MCP run **without** the desktop. Prefer fixing core + CLI first.

## Data flow (short)

- **Worktree threads** — one agent per git worktree (`thread/*`). Desktop / CLI / MCP create and drive them. After `git worktree add`, Orchestrator runs setup in the background in parallel with the first agent turn. Discovery order: `.sideboard` / `.conductor` `[scripts] setup`, then `.cursor/worktrees.json`, then conventional `script/setup` / `bin/setup` / `scripts/setup(.sh)`. `run_setup` re-runs the same chain. Create-from-PR stores `prUrl` immediately. Create-from-branch still forks `thread/<team>` from the chosen ref; if that source branch already has a GitHub PR, Sideboard looks it up (`gh pr view` / `gh pr list --head owner:branch`) and persists `prUrl` so the right-sidebar pill matches create-from-PR. Later `gh pr …` tries the persisted URL, then the worktree branch (a PR opened from this chat), then the source branch.
- **Orchestration (Global)** — coordinator agent uses Sideboard MCP (`list_threads`, `create_thread`, `send_to_thread`, `ask_git`, …). It does not live inside a project worktree. Fleet playbook is one document written as both `AGENTS.md` and `CLAUDE.md` in the synthetic home (Claude vs Codex/Cursor filenames). First-turn prompt adds audience, goal, and workspace inventory only — not a third copy of the playbook. Token totals are Claude-shaped (`inputTokens` uncached; cache extra). Codex and Brightsy report OpenAI-shaped usage (`cached_*` already inside input; Codex `reasoning_output_tokens` already inside output) — adapters subtract before the UI. Claude, Cursor SDK, and OpenCode already report additive cache.
- **Slack** — hosted relay `wss://relay.sideboard.cloud/slack/desktop`. OAuth callback `https://relay.sideboard.cloud/slack/callback` (client secret stays on Fly). Desktop Listen registers this Mac; DMs/@mentions go to the Global orchestrator. A follow-up DM/@mention force-stops the in-flight coordinator turn and starts a new one (same `clearQueue` stop as MCP `send_to_thread`); send `stop` to cancel without a replacement prompt. Compute stays on the Mac (VPN); the relay routes Slack chat only. The machine must stay awake. The same Fly app serves the marketing site at `https://www.sideboard.cloud/` (`site/`).

Desktop `predev` builds core. After core changes, rebuild core (or restart `pnpm dev`) before expecting the app to pick them up. The renderer may `import type` from `@sideboard-ai/core` but must not import values from the core barrel (that pulls Node `fs` into Vite). Value helpers go through `@sideboard/*` aliases in `apps/desktop/electron.vite.config.ts`.

**Nested Electron.** Sideboard.app leaks `ELECTRON_*` / `CHROME_*` (crashpad/GPU) into children. A nested Electron then dies at startup (`HasCustomHostObject` / `ElectronInitializeICUandStartNode`). Agent spawn and run scripts strip those keys. That is not enough when the immediate parent is also Electron — Cursor's local agent (Grok and other Cursor models) merges MCP env onto its own crashpad pipe, and the crash happens in `ElectronInitializeICUandStartNode` before JS can unset env. Cursor's SDK also spawns `.js` with `process.execPath` and strips `ELECTRON_RUN_AS_NODE` from child env — so an Electron-as-Node Cursor runner makes the local agent Sideboard.app (nested Chromium). The packaged app copies the Cursor runner, `@cursor/sdk`, `rg`, and the runner's production dependency tree (`execa`, `smol-toml`, SDK deps such as `zod` / `@bufbuild/protobuf`) into `Contents/Resources/cursor-runtime` (`extraResources`; `apps/desktop/scripts/stage-cursor-runtime.js`). Copying only the SDK package is not enough — ESM resolution cannot walk up to the repo `node_modules` from inside the app. Staging must also nest duplicate package names (pnpm's `get-stream@9` ESM for execa vs hoisted `get-stream@5` CJS for extract-zip) — flattening by name makes `import { getStreamAsArray } from 'get-stream'` throw. Shared copier: `apps/desktop/scripts/stage-node-deps.js`. Do not set `asarUnpack` — electron-builder `getRelativePath` requires every candidate under `apps/desktop`, and pnpm workspace links realpath into `packages/core`. Native `.node` modules still unpack via electron-builder's default smartUnpack. `resolveNodeLaunch` prefers a real `node` for those extraResources files.

**MCP is the CLI.** In-app agents and other Mac apps (Cursor IDE, Claude Code, Codex) spawn the same stdio server: system `node` + filesystem `run-stdio.js` (or `sideboard mcp`). Packaged Sideboard.app ships that entry in `Contents/Resources/sideboard-mcp` (`extraResources`; `apps/desktop/scripts/stage-sideboard-mcp.js`) with core's production dependency tree (`@modelcontextprotocol/sdk`, `execa`, `zod`, `@cursor/sdk`, …) and a Node-ABI `better-sqlite3`. Copying only sqlite is not enough — ESM resolution cannot walk up to the repo `node_modules` from inside the app. The isolated pack check must import `execa` (and fail on `SyntaxError` / named-export errors), not only `ERR_MODULE_NOT_FOUND`. MCP `command` is never Sideboard.app / Electron-as-Node when a system `node` exists. The board UI stays on in-process core/IPC. Packaged + other apps share `~/Library/Application Support/sideboard` (`SIDEBOARD_APP_DATA`). `pnpm dev` keeps `.sideboard/dev-app-data` so two orchestrators do not race one store. On packaged `app.whenReady()`, Sideboard merges a `sideboard` entry into `~/.cursor/mcp.json` (and `~/.claude.json` if that file already exists) pointing at the same absolute node + extraResources MCP + store. Codex is documented the same way; we do not rewrite `~/.codex/config.toml`. Every MCP serializer still drops `ELECTRON_RUN_AS_NODE` from spawn env. Cursor SDK `mcpServers` include `type: "stdio"`. Brightsy is hosted chat and does not spawn local MCP. Helpers live in `packages/core/src/hook/nested-electron-env.ts`, `packages/core/src/agents/node-launch.ts`, `packages/core/src/agents/packaged-runtime.ts`, `packages/core/src/agents/injected-mcp.ts`, and `packages/core/src/agents/user-mcp-config.ts`.

**Cursor local store.** Sideboard uses `@cursor/sdk` `JsonlLocalAgentStore` under app-data `cursor-sdk-store/` (Electron's Node has no `node:sqlite`). Agent rows point at a checkpoint `rootBlobId`; interrupted writes leave `.checkpoints.ndjson.*.tmp` and a missing blob. Resume then throws `Corrupt local agent checkpoint` or `Agent … not found`. The Cursor runner starts a fresh `Agent.create` (and the orchestrator retries once after clearing `sessionId`) instead of failing the turn.

**Cursor ripgrep.** The local agent indexes the worktree with `findFilesWithRipgrep`. The SDK walks from `argv[1]` for `node_modules/@cursor/sdk-<plat>-<arch>/bin/rg`. In the packaged app that path is inside `app.asar` (not executable), which surfaces as `findFilesWithRipgrep` + `[resource_exhausted]`. Spawn sets `CURSOR_RIPGREP_PATH` to `Contents/Resources/cursor-runtime/node_modules/@cursor/sdk-<plat>/bin/rg` (`packages/core/src/agents/cursor-ripgrep.ts`).

**Unattended git.** Agent and MCP children must not pop macOS Keychain or SSH passphrase dialogs during turns — orchestrator parents (desktop Global, MCP, Slack) cannot click them. Desktop `app.whenReady()` warms GitHub auth once (`gh auth token` or a stored PAT); Keychain is OK at that moment. The token is written to `~/.sideboard-git-auth/` (`git-credentials` + isolated `GH_CONFIG_DIR`, mode 0600). Agent env gets `GIT_CONFIG_*` (HTTPS `insteadOf`, `credential.helper=store --file=…`) and `GH_CONFIG_DIR` — **not** `GH_TOKEN` and not `http.extraHeader`. MCP start reuses those files and does not call `gh auth token` again. Account → GitHub mode `ssh` keeps SSH remotes but still batch-mode (fails instead of prompting); `gh` still uses the warmed config. Helpers: `packages/core/src/git/github-agent-auth.ts`, `git-auth-mode.ts`. All worktree agents share `spawnAgentTurn`; Sideboard MCP gets the same env in every serializer. Codex `workspace-write` needs `shell_environment_policy.inherit=all` + `ignore_default_excludes` so `GH_CONFIG_DIR` / `GIT_CONFIG_*` reach the sandbox, `sandbox_workspace_write.network_access=true`, and `sandbox_workspace_write.writable_roots` pointing at `--absolute-git-dir` plus `--git-common-dir` (Codex otherwise mounts `.git` read-only, so linked worktrees cannot create `index.lock` in the main repo’s `.git/worktrees/<name>/`). Setup/run scripts get the same git env. Brightsy is hosted chat and does not run local git.

**Cursor local hang.** Local SDK `send()` does not throw `agent_busy`. A killed runner leaves a persisted RUNNING run, and HTTP/2 stall retries can drop `toolCallCompleted` so the run never finishes. Each Cursor runner `send()` uses `local.force`, create/resume set `enableAgentRetries: false`, and SIGTERM/SIGINT cancel the live run (2s cap) before exit. Helpers live in `packages/core/src/agents/cursor-session.ts`. Do not default `useHttp1ForAgent` — that path has produced instant RUNNING→ERROR with no content. Merge/push still belong on `ask_git`, not a worktree prompt like `Merge PR.`

**Token-stream paint.** Claude `content_block_delta`, Cursor local `assistant`/`thinking`, and similar frames are often one word. `spawnAgentTurn` coalesces consecutive stdout/thinking (~32ms) before orchestrator IPC; the Cursor runner does the same before NDJSON. The orchestrator must not `readThread()` on stdout/thinking (sync JSON parse on the Electron main thread makes streaming look word-by-word). Helper: `packages/core/src/agents/cursor-stream-coalesce.ts`.

## Process skills

Recurring process guides are **Claude Code project skills** at `.claude/skills/<name>/SKILL.md` (committed). Sideboard discovers that folder (and `.cursor/skills`, legacy `.sideboard/skills`, …) for composer `/name` expand. Native Claude Code and `attach` load `.claude/skills` without Sideboard. New skills must not be written only under `.sideboard/skills`. The worktree playbook (`formatProcessGuideDirective`) and orchestrator playbook state this; the stock Review template asks reviewers to propose a sentence for `review.md` or a skill when a missing rule will recur.

This repo ships [`.claude/skills/graph-engineering/SKILL.md`](../../.claude/skills/graph-engineering/SKILL.md) (`/graph-engineering`) — the method for fan-out / batch work. `.cursor/skills/graph-engineering` is a symlink so Cursor sees the same file. `AGENTS.md` / `CLAUDE.md` point at it for Codex and OpenCode.
