# Sideboard

Instructions for agents working **in this git repo**.

Read [docs/system/README.md](docs/system/README.md) before changing code. Then open the docs that match the task:

- [docs/system/glossary.md](docs/system/glossary.md) — project, workspace, chat, agent
- [docs/system/architecture.md](docs/system/architecture.md) — packages, phone remote, MCP, desktop
- [docs/system/agent-rpc.md](docs/system/agent-rpc.md) — agent WebSocket JSON-RPC (Cursor worktree pilot; not an MCP shim)
- [docs/system/agent-orchestration.md](docs/system/agent-orchestration.md) — `taskState`, A2A fit
- [docs/system/conventions.md](docs/system/conventions.md) — build, test, PRs
- [docs/system/safety.md](docs/system/safety.md) — land/purge, secrets, remote control
- [docs/system/deploy.md](docs/system/deploy.md) — marketing site + relay (Fly)
- [docs/system/slack-marketplace.md](docs/system/slack-marketplace.md) — legacy notes. The remote is the phone app, not Slack

When you make an architecture decision (where something lives, how a host is split, a deploy path, a safety rail), write it into `docs/system/` in the same change — not only in chat or a code comment.

Recurring multi-item work (migration, port, batch fix, fan-out): follow [`.claude/skills/graph-engineering/SKILL.md`](.claude/skills/graph-engineering/SKILL.md) (`/graph-engineering`). New Sideboard host methods for agents: [`.claude/skills/agent-rpc/SKILL.md`](.claude/skills/agent-rpc/SKILL.md) (`/agent-rpc`) — WebSocket JSON-RPC owned by desktop, not MCP stdio. Desktop / npm version cuts: [`.claude/skills/release/SKILL.md`](.claude/skills/release/SKILL.md) (`/release`). After merge-from-main or a hung `pnpm install` across worktrees: [`.claude/skills/worktree-install/SKILL.md`](.claude/skills/worktree-install/SKILL.md) (`/worktree-install`) — use the worktree-local store, never a shared `~/.pnpm-store`. Recently merged PRs with un-addressed Cursor Bugbot / cursorbot review comments: [`.claude/skills/bugbot-follow-ups/SKILL.md`](.claude/skills/bugbot-follow-ups/SKILL.md) (`/bugbot-follow-ups`) — collect unresolved threads, triage against `origin/main`, one follow-up PR. A miss that will recur (you made it twice, or a person told you the rule): [`.claude/skills/skill-improver/SKILL.md`](.claude/skills/skill-improver/SKILL.md) (`/skill-improver`) — one sentence in the skill that owns it, in this change, before the turn ends. Any long worktree job (pack, test, deploy): `/long-running` (Sideboard product skill for every worktree; this repo also has [`.claude/skills/long-running/SKILL.md`](.claude/skills/long-running/SKILL.md) for Mac-release notes) — `detached-job.cjs start` then loop `wait` and `present_artifact` `type=log` with `delta` (do not ask the human to poll). `stop_job` if it hangs or is doing the wrong thing. A server that should stay up (a local site preview) is not a detached job — stop it instead of waiting; it never finishes. Connector CLIs: write output to `.context/cli/` (not `.context/attachments/`) and read a slice — never dump raw `--json` / `--expand` into a tool result. Phone or marketing screenshots from the simulator: [`.claude/skills/phone-screenshots/SKILL.md`](.claude/skills/phone-screenshots/SKILL.md) (`/phone-screenshots`) — hide Expo Go’s tools button only for the capture, then turn it back on. Do not patch the app. In the same turn a pull request merges to the default branch, follow [`.claude/skills/announce-on-x/SKILL.md`](.claude/skills/announce-on-x/SKILL.md) (`/announce-on-x`) — post or skip each pull request that merge landed on the default branch, from the brand guide. Do not schedule a catch-up. New process guides go in `.claude/skills/<name>/SKILL.md`, not `.sideboard/skills`.

A daily self-improvement loop, based on [docs/ROADMAP.md](docs/ROADMAP.md): [`.claude/skills/self-improvement/SKILL.md`](.claude/skills/self-improvement/SKILL.md) (`/self-improvement`). The morning automation is that loop. The competition scan informs that judgment. A survey of the supported agents (Claude Code, Codex, OpenCode, Cursor, Brightsy, Gemini CLI, Copilot CLI) and connector CLIs (`vercel`, `supabase`, `sentry-cli`) informs it the same way. Incorporate a dated advance only when that is the best next step. [docs/ROADMAP.md](docs/ROADMAP.md) is the default order. Change a line when it is not the best path, given how the code and the UI are implemented today (`docs/system/architecture.md`, `docs/system/conventions.md`, the desktop board, and the phone). UI conventions and coding conventions can change when keeping them is not the best path. Each run starts from the last outcome in `~/.sideboard/self-improvement-queue.json` and recommends one undone slice of the unfinished Now item, then Next, when that slice is still the best next step. Otherwise the one recommendation is a change to the roadmap line, or to a UI or coding convention that is in the way. A day with no new peer fact still recommends that slice when it is the best path. A dated peer fact can point the slice at a different Now or Next item, or make a marketing or prior-call change the one recommendation. A skipped or deferred slice stays out until a new fact makes that outcome the wrong product. The loop then takes the next open slice when that slice is still the best path, a roadmap change when that slice is the wrong path, or a change to a UI or coding convention when that convention is in the way. A convention row is `kind: convention`: the current behavior, the better behavior, and the paths. The skill is the procedure. The report stays in that chat and in `~/.sideboard/self-improvement.md`. When a new file is missing, rename its old pair into place before creating it: `~/.sideboard/competition-scan-queue.json` to `~/.sideboard/self-improvement-queue.json`, and `~/.sideboard/competition-scan.md` to `~/.sideboard/self-improvement.md`. Do not keep two logs. Do not create a new file while its old name still exists. When there is one recommendation, the run queues it and asks before opening a worktree. The child that develops the slice starts that worktree's Dev app with `run_dev_script` and exercises the change before the pull request. `preview=url` means open the returned URL. `preview=window` means the Electron window is the app (`SIDEBOARD_PORT`, never a guessed `:3000`). The desktop app is electron-vite. The phone is Expo, on its own port. A docs-only or copy-only slice starts no Dev app. A UI slice is judged for visual design as well as behavior. Computer use is Settings → Advanced, off by default (`computer_use`). A quiet day does not ask. A prior-call line moves only after Approve. Do not open a pull request from this chat. After that pull request merges, and after a Fly deploy when `site/` changed, follow `/announce-on-x`.

**Reading run script logs:** Dev terminal and other run script output are persisted to `~/.sideboard/threads/wt-{hash}-run-{script}.run.log.json`. Agents can call the MCP tool `get_run_log` (ref omitted on worktree turns) to read the tail of any script's output. CLI: `.context/cli/read-dev-log.sh [worktree] [script-name]` for manual access.

`CLAUDE.md` is only `@AGENTS.md`. Edit this file. Cursor loads both filenames; the import keeps it from loading these instructions a second time.
