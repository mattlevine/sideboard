Why it exists

Started as a local port. Kept the rest on this machine.

When Conductor moved the interesting part of a worktree board into a paid cloud, Sideboard began as an open port of the local loop. Then came the pieces that still belong on this Mac: an orchestration tier, a kanban of the fleet, Slack so you can reach it from somewhere else, and CLI / MCP so other systems can drive it — without moving the repo off the network you already sit on.

Conductor is the polished Mac board (and a $50/mo cloud). Orca is the agent IDE — terminals, browser, mobile. Sideboard is the local orchestration layer both of those leave on the table.

Questions

How is this different from Conductor?

Conductor’s free Mac app is a polished human board around local worktrees. Their paid product is cloud sandboxes, multiplayer, a cloud API, and a mobile app. Sideboard keeps orchestration on this machine: MCP, a kanban, Slack to the Mac, CLI. Use Conductor if you want their finished workspace UI or always-on Vercel sandboxes. Use Sideboard if the fleet should stay on the VPN you already sit on.

How is this different from Orca?

Orca is an agent development environment — terminals, embedded browser, design mode, many CLI agents, mobile companion, Windows and Linux. Sideboard is not trying to be an IDE. It is the orchestration tier: a board, an agent that can drive other threads, and remotes (Slack, CLI, MCP) so other systems can reach this Mac.

Do I pay Sideboard for models?

No. Bring the Claude, Codex, OpenCode, or Cursor subscriptions you already have. Sideboard is Apache-2.0. The desktop and CLI are free. You are not renting a sandbox from us.

Does it keep running if I close the laptop?

No — that is the cloud-sandbox trade. Slack and scheduled jobs reach this Mac only while it is awake. Opt in to caffeinate from Settings → Advanced (or from an orchestration chat) when you step away. If you need always-on off-VPN compute, Conductor Cloud and similar sandboxes are the fit.

Can I use it without the desktop app?

Yes. npm i -g @sideboard-ai/cli ships the CLI and the stdio MCP server. The desktop is the board and the Slack listener.

It fits if…

You already run several local CLI agents on a Mac — especially one on a corporate VPN — and you want an orchestrator you can see, an agent can drive, and Slack / MCP / CLI can reach. Extra fit when the agent produces structured content or HTML that should sit next to the diff.

Use something else if…

You want a polished local board and will never touch CLI or MCP (Conductor free), you want always-on cloud workspaces, you want a full agent IDE (Orca), you live in an IDE-native agents window, or you are on Windows or Linux.
