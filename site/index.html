The loop, not just the board.

Worktrees are the shared primitive — every tool in this category has them. Sideboard owns what happens before and after: where the work came from, what the agent produced, and whether it is ready to land.

In

Start from the ticket, not a blank prompt

Create a worktree from a Linear, GitHub, or AbleTime issue, a branch, or a PR. The agent gets the ticket, the repo, and the services your project uses — Vercel, Supabase, PostHog, Sentry — through official CLIs with tokens that stay in the Mac vault. Several chats can share one worktree when a ticket needs more than one agent.

Out

Review what they built, not only the diff

A worktree chat puts the agent thread, the git repo (Files, Changes, CI, Review), and a structure column side by side. The agent can open an HTML artifact, render a JSON Schema as a table or form you can edit, or show a file manager — so the content, data, and documents it produced get reviewed next to the code, before you land.

MCP

An orchestrator that is itself an agent

It can list threads, wait on a turn, read a diff, fork a worktree, ask a worktree to commit or open a PR, and open a pane in the desktop. Mechanical control — list, send, diff, land — stays on the CLI at zero tokens. MCP is for judgment across the fleet. land and purge stay human-only.

Cron

Run the loop while you are not looking

Local jobs send a prompt to a chat at a time, on an interval, or on a cron — triage open PRs every hour, a morning standup, a nightly smoke run. Jobs fire on this Mac, and Sideboard keeps it awake while schedules are enabled. Agents can create schedules too.

sideboard schedule add --prompt "Triage open PRs" --every 1h
sideboard schedule add --prompt "Morning standup" \
  --cron "0 9 * * *" --tz America/Los_Angeles
sideboard schedule add --prompt "Smoke the release" \
  --at 2026-10-12T18:00:00-07:00 --thread <id>
sideboard schedule ls
Remote

Your phone, the CLI, or any MCP client

Pair the phone from Settings → Remote and pick which Mac to open; message text goes through the relay, agents and repos stay here. Register the MCP with Claude, Codex, OpenCode, or Cursor and that agent sees the fleet from outside Sideboard. attach drops you into the same session in the native CLI. adopt brings existing worktrees in.

Where it sits

Conductor is the board. Orca is the IDE. Herdr is the runtime.

All three run agents in worktrees, and all three are good at it. Sideboard is the control plane around that: the ticket the work came from, the review of everything the agent made, the PR, the schedule — on the Mac that is already on your VPN with your git login and your internal APIs.

Only one of them moves the agents off that machine: Conductor's $50/mo cloud. Sideboard started as a local port of that loop and kept building on the Mac.

Questions

How is this different from Conductor?

Conductor's free Mac app is a finished workspace UI around local worktrees. Their paid product is cloud sandboxes, multiplayer, a cloud API, and a mobile app. Sideboard keeps the loop on this machine and adds the parts around the board: tickets in, an orchestrator agent, review of artifacts and data as well as the diff, schedules, and a phone to this Mac. Use Conductor if you want their UI or always-on Vercel sandboxes. Use Sideboard if the fleet should stay on the VPN you already sit on.

How is this different from Orca?

Orca is an agent IDE — terminals, embedded browser, inline diff comments, 27 agent CLIs, a CLI and MCP that agents can drive, a mobile companion, Windows and Linux. Sideboard is not an IDE. It is where the work comes from and goes to: the ticket, the schedule, the review of what the agent produced, the PR. Use Orca if you want the whole environment on any OS. Use Sideboard if you want the loop around it on a Mac.

How is this different from Herdr?

Herdr is a terminal runtime: a background server owns your agents' terminals so they keep running when you close the client or lose SSH, with a sidebar of who is working, blocked, or idle, and a CLI and socket API agents can drive. Sideboard does not own terminals. It owns the loop — tickets, review, PRs, schedules — and shows the fleet as a kanban by PR state. If you want terminals that outlive your laptop lid across machines, use Herdr; adopt can bring a worktree it created onto the Sideboard board.

Do I pay Sideboard for models?

No. Bring the Claude, Codex, OpenCode, or Cursor subscriptions you already have. Sideboard is Apache-2.0. The desktop and CLI are free. You are not renting a sandbox from us.

Does it keep running if I close the laptop?

No — that is the trade for keeping everything on this machine. The phone and scheduled jobs reach this Mac only while it is awake. Opt in to caffeinate from Settings → Advanced (or from an orchestration chat) when you step away. If you need always-on, off-VPN compute, Conductor Cloud is the fit; if you need terminals that survive a closed lid, Herdr is.

Can I use it without the desktop app?

Yes. npm i -g @sideboard-ai/cli ships the CLI and the stdio MCP server. The desktop is the board. The phone app talks to that desktop.

It fits if…

You run Claude Code, Codex, OpenCode, or Cursor on a Mac — especially one on a corporate VPN — and you want the loop around them: tickets in, an orchestrator you can see and an agent can drive, a review of what they built, PRs out, on a schedule, from your phone.

Use something else if…

You want always-on sandboxes off your machine (Conductor Cloud), a full agent IDE with many harnesses on any OS (Orca), or terminals that outlive your laptop lid across machines (Herdr). Sideboard is Mac-only and the Mac has to stay awake.
